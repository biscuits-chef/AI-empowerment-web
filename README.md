# 企业智能问答前端

这是与 `intelligent-qa-audit-service` 配套的 React 前端工程母版。界面按[飞书交互原型](https://my.feishu.cn/wiki/HC7Dwym3Vi2jbikwnq6cMqhhnUf?from=from_wechat)重构为“智浦小鹿”统一工作台，支持聊天管理、任务输入、可恢复执行过程、安全 Markdown 结果、停止生成、复制、赞踩、重新生成、引用来源以及双通道证据冲突提示。左侧会话栏默认展开并与主工作区并列，支持折叠和恢复；Agent 仅在输入框下拉菜单中选择，第一阶段默认且仅开放“智能问数”，左侧栏不再重复展示 Agent 目录。

## 快速启动

环境要求：Node.js 20.19 及以上版本，推荐使用 Node.js 24。

```bash
npm ci
npm run dev
```

默认把同源 `/api` 请求代理到 `http://127.0.0.1:8080`。需要同时运行另一套后端联调实例时，可通过 `VITE_DEV_API_TARGET` 覆盖代理目标，例如：`VITE_DEV_API_TARGET=http://127.0.0.1:18080 npm run dev -- --port 5174 --strictPort`。

本地地址为 `http://localhost:5173`，开发服务器会把 `/api` 转发到 `http://127.0.0.1:8080`。后端必须提供已认证的用户身份；生产环境应由统一登录或网关完成认证。

完整质量检查：

```bash
npm run verify
```

## 环境配置

浏览器始终读取 `/config/application.xml`，业务配置不会在构建时写死。三套模板位于：

- `deploy/config/application-dev.xml`
- `deploy/config/application-test.xml`
- `deploy/config/application-prod.xml`

容器通过 `APP_PROFILE=dev|test|prod` 选择模板，通过 `BACKEND_UPSTREAM` 指定后端地址。XML 只能存放可公开给浏览器的参数，禁止写入密钥、令牌和内部凭证。

```bash
docker compose up --build
```

默认访问地址为 `http://localhost:8081`。

## 目录说明

```text
src/
├── domain/                 领域类型和业务状态
├── application/            用例编排、端口和状态机
├── infrastructure/         XML 配置、HTTP 和流式协议适配
└── presentation/           页面组件和样式
```

依赖只能由外向内：展示层和基础设施层依赖应用层端口，应用层依赖领域类型；领域层不依赖浏览器和 React。

## 已实现功能

- 新建、选择、搜索、重命名和删除聊天；左侧列表按浏览器本地自然日分为“今天、昨天、更早”。
- 会话列表使用后端稳定游标分批加载和前端虚拟滚动，长列表不会一次挂载全部会话节点。
- Agent 目录由前端本地配置，不调用 `/api/v1/agents`；选择器仅在新建会话首次提问前展示，一期默认且仅开放“智能问数”。首问携带 `agentType=SMART_DATA`，进入已有会话后隐藏且锁定选择，后续提问不发送该字段；其他入口固定提示“该功能尚未开放”且不会创建会话。
- 首页显示“今天想完成什么？”、当前 Agent 和双通道标识；快捷任务只填充草稿，不会未经确认直接执行。
- 新聊天在第一次有效提问时才创建并落库，空白草稿不会产生历史会话。
- 修改名称和删除使用页面内对话框，支持点击空白区域或按 `Esc` 关闭，不依赖浏览器原生弹窗。
- 执行中会话删除由后端拒绝，页面提示“会话正在执行，请停止后删除”。
- 提交问题并实时显示回答生成阶段；执行过程、执行结果和来源/产物分区展示，过程可展开恢复。
- 回答支持标题、列表、代码和表格等受控 Markdown 展示，原始 HTML 不会被执行。
- 知识库与业务数据库双通道核验状态展示。
- 数据不一致时显示醒目的人工复核提示。
- 指代不明确或存在多个候选时显示追问，用户可继续输入序号、完整名称或唯一标识；刷新后保留真实追问状态。
- 停止生成采用服务端取消协议，不把断开页面连接误当作取消。
- 正常生成的历史问答保留；重新生成会把原问题作为新的用户消息再次提交，重新执行完整问答链路，不覆盖旧问题和旧答案。
- 回答复制、喜欢、不喜欢和重新生成。
- 流式断线事件缺口自动回退到服务端已保存答案快照。
- 刷新或重新进入会话后恢复回答执行过程、来源/产物、人工复核提示和真实状态；活动回答继续跟随持久事件。
- 发送问题后保持页面稳定；未处理渲染异常由错误边界显示恢复入口，不再直接白屏。
- 会话加载期间禁用提问，快速切换时忽略过期消息响应。
- 2026-09-14 范围调整后一期不支持文件上传；输入区不显示上传控件、不响应拖拽文件，问题请求不发送 `files` 字段。开发期历史附件只做兼容只读展示。
- 浅色、深色、移动端布局和键盘可访问性。

## Codex 自主开发

Codex 开始工作前会读取 `AGENTS.md`、需求、架构决策和对应技能。推荐入口提示词见 `CODEX_MASTER_PROMPT.md`。任何功能只有通过 `npm run verify`、完成安全和可访问性检查后才算交付。

编码时必须遵守中文注释规范：所有类型、接口、类型字段、类、成员字段、构造器和命名函数使用中文 TSDoc；每个可命名入参使用中文 `@param`，有返回值的函数用中文说明返回结果。流式事件、状态转换、幂等、重连、降级和安全边界使用中文行内注释解释设计原因。注释不得逐行复述代码，不得保留注释掉的旧实现，协议字段和第三方术语可以保留英文。

`npm run comments:check` 会扫描 TypeScript/TSX 源码；遗漏类型、字段、函数、入参或返回值的中文注释时，`npm run verify` 会直接失败。
