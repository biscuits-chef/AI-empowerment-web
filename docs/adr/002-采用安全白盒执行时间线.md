# 架构决策：采用安全白盒执行时间线

- 状态：已接受
- 日期：2026-09-08
- 决策人：项目组

## 背景

现有页面只把执行事件展示为简单日志，用户无法快速判断当前在理解问题、查询哪个通道、是否取得数据、两个通道是否一致，以及失败发生在哪个阶段。直接展示提示词、思维链或原始 SQL 又会引入安全、隐私和提示词攻击风险。

## 备选方案

1. 展示所有内部日志：信息最多，但会泄露实现、地址、SQL、提示词和敏感载荷，不可接受。
2. 继续只展示当前状态文案：实现简单，但无法满足用户核验过程的需要。
3. 将服务端结构化事件折叠为五阶段安全时间线：展示流程、状态、数量、耗时和核验结论，同时禁止内部敏感内容进入展示事件。

## 决策

采用第三种方案。页面固定展示问题理解、知识库检索、GoldenDB 查询、双通道核验、回答生成与保存五个阶段。服务端提供场景、计划版本、意图、置信度、查询条件数量、两个通道返回数量、核验状态、冲突数量和阶段时间。前端只解析稳定编码，不从回答正文猜测阶段。

禁止展示或保存到白盒事件中的内容包括：系统提示词、思维链、原始 SQL、服务地址、密钥和证据正文。运行编号可展示，便于用户与支持人员定位问题。

## 后果

用户可以实时了解执行位置并在刷新后恢复轨迹，故障和证据冲突也更容易解释。协议增加数个向后兼容的事件类型；旧回答缺少完成事件时只能推断阶段结束，不能恢复历史结果数量。

## 验证

通过事件转换单元测试、组件测试、SSE 回归测试、桌面与移动浏览器检查验证；后端确保历史事件持久化，前端确保提示词和 SQL 不进入页面。
