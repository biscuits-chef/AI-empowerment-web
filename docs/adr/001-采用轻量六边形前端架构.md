# 架构决策：采用轻量六边形前端架构

- 状态：已接受
- 日期：2026-08-24
- 决策人：项目组

## 背景

问答页面需要处理聊天管理、幂等提交、流式事件、取消、重放恢复、反馈和后续合同审核扩展。若组件直接依赖接口细节，协议变化会扩散到整个界面，测试也需要真实网络。

## 备选方案

1. 组件直接调用接口：初始代码少，但耦合、重复错误处理和测试成本高。
2. 全量领域驱动框架：边界清晰，但对当前规模过重。
3. 轻量六边形架构：保留领域、应用端口、基础设施和展示边界，不引入额外框架。

## 决策

选择第三种方案。`QaGateway` 是远端问答能力端口，HTTP 与流式实现位于基础设施层；React 组件只调用应用控制器。领域层只定义交互所需的状态和不变量。

会话时间分组属于展示规则，使用后端 `updatedAt` 与浏览器本地自然日计算“今天、昨天、更早”，不改变领域对象或远端契约。重新生成成功后，应用层把原问题作为新用户消息追加并订阅新回答；服务端负责创建新的问答记录和执行完整链路，展示层不得覆盖旧问答。

## 后果

协议替换、模拟测试和功能扩展更容易，但新增功能必须判断归属层，文件数量略有增加。禁止为了形式创建无业务价值的接口。

## 验证

通过静态依赖审查、端口替身组件测试、流式解析测试和完整质量脚本验证。
