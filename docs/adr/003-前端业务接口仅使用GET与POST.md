# 架构决策：前端业务接口仅使用 GET 与 POST

- 状态：已接受
- 日期：2026-09-14
- 决策人：用户确认

## 背景

既有 HTTP 网关以 PATCH 修改会话、DELETE 删除会话和文件，并以 PUT 提交回答反馈。用户明确要求前端与后端交互时只使用 GET 和 POST。该约束会同时影响网关实现、后端路径、接口文档、发布顺序和后续功能开发。

## 备选方案

1. 保留既有 REST 方法：路径简洁，但不满足已确认的方法白名单。
2. 把所有状态变更映射为同一路径上的 POST：路径变化较少，但不同命令需要依赖请求体分派，接口语义和审计记录不清晰。
3. 使用 POST 与全局唯一的显式动作路径：查询保持 GET，状态变更使用 POST，并用 `/creation`、`/upload`、`/rename`、`/deletion` 等路径区分命令。

## 决策

选择第三种方案。前端 `QaGateway` 的所有普通调用和 SSE 订阅只允许 GET 或 POST。GET 仅用于读取；提问、修改、删除、反馈、停止和重新生成统一使用 POST。每项操作必须使用唯一 URL，不能再依靠 GET/POST 区分相同路径。首次提问与会话创建合并调用 `/questions/submission`，会话重命名调用 `/chats/{chatId}/rename`，会话删除调用 `/chats/{chatId}/deletion`。回答反馈保留原路径并改用 POST。

2026-09-14 一期范围调整后不支持文件上传，因此一期网关不注册文件上传或删除方法。后续阶段若重新启用文件能力，其状态变更仍必须遵循本决策的 POST 与唯一动作路径约束。

展示层和应用层不得直接发起 HTTP 请求或绕过网关。旧方法不保留兼容调用，避免方法白名单产生例外。

## 后果

前端和后端必须在同一发布窗口升级，旧前端不能与新版后端长期混用。路径中的动作名称增加，但网关规则、调用审计和自动化检查更明确。回滚时必须同时恢复前后端契约，不涉及业务数据回滚。

## 验证

`HttpQaGateway` 契约测试执行全部普通接口并逐项断言 URL 与方法，所有方法必须属于 GET/POST 白名单且所有 URL 必须唯一；SSE 测试断言订阅仍使用 GET。完整执行 `npm run verify`，后端同步执行运行时映射门禁和 Maven 完整门禁。
